# 白背景の商品画像を作る共有スクリプト

ユーザー指定方式：元画像から商品を切り抜き、元画像全体にトーンカーブを適用した下地へ重ねる。下地にも商品の形が残るため、マスクの不足部分を補完できる。商品を描き直さず、不透明な商品部分は元画像のRGBを保持する。

## 実行

リポジトリ直下で、requirements.txtをインストールしたPythonを使用する。

```sh
python3 scripts/product_white_background.py /path/to/source.jpg \
  --output-dir output/white-background/model-color \
  --knee 160 --white-point 235
```

切り抜きはアプリと同じU2NetPを使用する。モデルは既存の `U2NET_HOME/u2netp.onnx`（未指定時は `~/.u2net/u2netp.onnx`）を使用し、なければ既存ワーカーがダウンロードする。背景加工APIは別の保存・分離工程を持ち、このCLIへの切り替えはしていない。

手修正したマスクや切り抜きPNGがある場合は再推論せず利用できる。

```sh
python3 scripts/product_white_background.py /path/to/source.jpg \
  --mask /path/to/product-cutout.png \
  --output-dir output/white-background/model-color
```

マスクは白=商品、黒=背景。RGBAならアルファを使う。元画像と同じサイズ・構図で渡す。切り抜きPNGのRGBは使わず元商品のRGBを使用する。

## トーンカーブ

初期値は (0,0) → (160,160) → (235,255) → (255,255)。RGB各チャンネルへ同じ折れ線カーブを適用する。235以上を純白へ飛ばし、160以下を維持する。単純な露光増加ではない。背景が残る場合はwhite-pointを下げる。影が消える場合は上げる。数値は全商品で成立する確定値ではなく、画像ごとの調整開始値。

不透明の商品は上層で元画素を保持する。半透明の境界は下地と混ざり、切り抜き不足部分は補正後の下地が見えるため、白いソールの階調や細い紐まで完全に復元できる保証はない。柄背景・色背景・文字入り画像は対象外。商品と背景の明度が近い画像ではマスクを修正する。

## 出力と確認

- `original.png`：EXIFの向きを反映した元画像。
- `mask.png`：商品マスク。
- `base-white.png`：商品も含む、トーンカーブ補正済みの下地。
- `product.png`：元画素の商品とマスクの透過PNG。
- `white.png`：完成画像。背景は#FFFFFFを目標に、接地影を残す。
- `recipe.json`：入力パス・原本SHA-256・カーブ設定・マスクの由来・処理バージョン。

原寸で、背景の灰色の残り、影の連続性、ソール・紐・ストラップの欠け、商品の色を元画像と比較する。完成画像は自動でFigma・Drive・共有ライブラリへ保存しない。元画像を上書きしない。

参考：既存の `output/amazon-20260921/side-refined/refine.py` は、背景の明度ムラを推定して影を抽出し、保護した商品画素を重ねた方式。この共有CLIはユーザーが指定した「元画像へのトーンカーブ＋商品レイヤー」を明示的に実装し、当時の35枚の処理をそのまま再現するものではない。

検証（2026-10-14）：CLASSIC WHITEの元画像でU2NetPから実行。white-point=235では上部に薄いグレーが残ったため220へ調整。四隅のRGB=(255,255,255)と、アルファ255の商品画素の元画像との完全一致を確認。接地影の確認も行った。この設定を他商品へ一律適用する前に比較する。
